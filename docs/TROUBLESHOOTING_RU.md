# Диагностика AWGM Admin

[Главная](../README.md) · [English](TROUBLESHOOTING_EN.md) · [Переменные окружения](ENVIRONMENT_RU.md)

В интерфейсе код ошибки находится в раскрываемом блоке «Технические данные». Ошибка запуска записывается одной строкой с префиксом `AWG_ADMIN_STARTUP_ERROR`. Журнал можно посмотреть командой:

```routeros
/log/print where message~"AWG"
```

При нескольких серверах код относится к выбранному серверу. Ошибка одного полностью настроенного дополнительного сервера не останавливает панель, если доступен хотя бы один другой сервер. Если не работает ни один сервер, панель останавливается; исключение — `MIKROTIK_PERMISSION_DENIED`, при котором диагностический интерфейс остаётся доступным.

## Ошибки параметров до запуска

Эти ошибки не имеют отдельного кода: контейнер завершается, а строка журнала начинается с `AWG_ADMIN_STARTUP_ERROR`.

| Сообщение или его часть | Причина и решение |
|---|---|
| `Missing required environment variables: ...` | Не заполнены перечисленные обязательные переменные. Для первого сервера нужны `MIKROTIK_HOST`, `MIKROTIK_USERNAME`, `MIKROTIK_PASSWORD`, `AWG_CLIENT_ENDPOINT` и, при включённой авторизации, `SESSION_SECRET`. Для объявленного дополнительного сервера проверьте четыре переменные с его суффиксом, например `_2`. |
| `... must be yes/no, true/false, on/off or 1/0` | Булева переменная содержит неподдерживаемое значение. Используйте одну из перечисленных пар значений. |
| `... must be an integer` | В числовой переменной указано не целое число. Исправьте значение переменной, названной в сообщении. |
| `... must be between ... and ...` | Число или порт вне допустимого диапазона. Укажите значение внутри диапазона из сообщения. |
| `AWG_CLIENT_ENDPOINT... must use host:port format` | Endpoint задан без порта. Используйте формат `host:port`, например `vpn.example.org:51820`. |
| `AWG_CLIENT_ENDPOINT... host is empty` | Перед двоеточием отсутствует адрес сервера. Укажите IP-адрес или DNS-имя. |
| `AWG_CLIENT_ENDPOINT... port must be an integer` | После двоеточия указан нечисловой порт. |
| `AWG_CLIENT_ENDPOINT... port must be between 1 and 65535` | Укажите допустимый номер порта. |
| `DEFAULT_THEME must be dark or light` | Установите `DEFAULT_THEME=dark` или `DEFAULT_THEME=light`. |
| `DEFAULT_LANG contains unsupported characters` | В коде локали допустимы только буквы, цифры, `_` и `-`. Для встроенных локалей используйте `ru` или `en`. |
| `UNKNOWN: ...` | Непредусмотренная ошибка загрузки приложения или локалей. Сохраните полную строку журнала, проверьте целостность образа и создайте обращение в [GitHub Issues](https://github.com/Vozdr/awgm-admin/issues). |

Полное описание переменных и их диапазонов приведено в [справочнике параметров](ENVIRONMENT_RU.md).

## Подключение к MikroTik

| Код | Что означает | Что сделать |
|---|---|---|
| `MIKROTIK_UNREACHABLE` | Не удалось установить TCP- или TLS-соединение с API. | Проверьте `MIKROTIK_HOST`, `MIKROTIK_API_SSL`, `MIKROTIK_API_PORT`, доступность сервиса `api`/`api-ssl` и ограничение адресов в `/ip/service`. Для самоподписанного сертификата либо установите доверенный сертификат, либо задайте `MIKROTIK_SSL_VERIFY=no`. |
| `MIKROTIK_AUTH_FAILED` | MikroTik отклонил логин или пароль. | Проверьте `MIKROTIK_USERNAME` и `MIKROTIK_PASSWORD`, а также что пользователь RouterOS существует и не отключён. |
| `MIKROTIK_PERMISSION_DENIED` | У пользователя API недостаточно прав для команды. | Назначьте группе пользователя политики `read,write,sensitive,api`. `sensitive` требуется для получения приватного клиентского конфига. После изменения прав повторите операцию; перезапуск панели не нужен. |
| `MIKROTIK_CONNECTION_LOST` | Соединение было закрыто во время команды, истёк таймаут или получен некорректный ответ API. | Проверьте связь с MikroTik и журнал RouterOS. При медленном устройстве увеличьте `MIKROTIK_COMMAND_TIMEOUT`; затем повторите операцию. |
| `MIKROTIK_RESOURCE_NOT_FOUND` | MikroTik сообщил, что запрошенный объект больше не существует. | Обновите список в панели. Если объект был удалён вручную, повторите действие уже с актуальными данными. |
| `MIKROTIK_API_ERROR` | RouterOS отклонил команду по причине, не относящейся к правам или отсутствующему объекту. | Раскройте технические данные: там находится ответ RouterOS. Исправьте указанную причину и повторите операцию. |

Для проверки API на MikroTik:

```routeros
/ip/service/print where name="api" or name="api-ssl"
/user/print detail where name="awgm-admin"
```

## Контейнер AWG и WireGuard

| Код | Что означает | Что сделать |
|---|---|---|
| `AWG_CONTAINER_NOT_FOUND` | Контейнер с `name` или `comment`, равным `AWG_CONTAINER_NAME`, не найден либо был удалён во время операции. | Выполните `/container/print detail`, исправьте `AWG_CONTAINER_NAME` в env AWGM Admin или восстановите контейнер. Затем перезапустите панель, если ошибка возникла при запуске. |
| `AWG_ENVLISTS_MISSING` | У AWG-контейнера не назначен ни один список в поле `envlists`. | Назначьте контейнеру один или несколько списков окружения. AWGM Admin объединяет переменные из всех указанных списков. |
| `AWG_ENV_INVALID` | В объединённых `envlists` отсутствует обязательный ключ либо во время операции исчезла управляемая запись. | По техническим данным определите ключ. Для запуска обязательны `AWG_MODE`, `AWG_LISTEN`, `AWG_REMOTE`, `AWG_JC`, `AWG_JMIN`, `AWG_JMAX`, `AWG_S1`, `AWG_S2`, `AWG_H1`–`AWG_H4`, `AWG_SERVER_PUB`, `AWG_CLIENT_PUBS`. Не удаляйте запись `AWG_CLIENT_PUBS`: панель обновляет её при изменении peers. |
| `AWG_MODE_INVALID` | Значение `AWG_MODE` отличается от `server`. | Установите `AWG_MODE=server` в одном из назначенных AWG-контейнеру списков. |
| `WG_INTERFACE_NOT_FOUND` | Не найден ровно один интерфейс WireGuard, чей `public-key` совпадает с `AWG_SERVER_PUB`. | Сравните `/interface/wireguard/print detail` и `/container/envs/print detail`. Исправьте ключ; если совпадений несколько, оставьте его только у нужного интерфейса. |
| `WG_INTERFACE_DISABLED` | Найденный интерфейс WireGuard отключён. | Включите интерфейс на MikroTik. |
| `WG_ADDRESSES_MISSING` | На найденном интерфейсе нет активного IPv4-адреса. | Добавьте и включите адрес с маской подсети в `/ip/address`. Из этой подсети панель выдаёт адреса клиентам. |
| `AWG_WG_PORT_MISMATCH` | Порт в `AWG_REMOTE` не совпадает с `listen-port` интерфейса WireGuard. | Укажите один внутренний порт в обеих настройках. Внешний endpoint клиента при этом может использовать другой порт. |
| `PROXY_RESTART_FAILED` | После изменения `AWG_CLIENT_PUBS` запущенный AWG-контейнер не остановился или не запустился за отведённое время. | Проверьте `/container/print detail` и журнал AWG-контейнера. Устраните причину отказа и запустите контейнер вручную; затем проверьте синхронизацию ключей в панели. |

Остановленный AWG-контейнер сам по себе не является критической ошибкой. Поведение описано ниже в разделе о сообщениях журнала.

## Изменение настроек сервера

| Код | Что означает | Что сделать |
|---|---|---|
| `ENVLIST_NOT_ASSIGNED` | Указанное имя `envlist` уже есть в `/container/envs`, но этот список не назначен текущему AWG-контейнеру. | Выберите envlist этого контейнера или укажите уникальное имя для нового envlist. |
| `ENV_VARIABLE_DUPLICATE` | Переменная с таким именем уже существует в выбранном envlist. | Используйте другое имя переменной или выберите другой envlist. |
| `ENV_VARIABLE_MANAGED` | Попытка вручную изменить, отключить или удалить переменную, которой управляет панель. | Обновите окно настроек. `AWG_CLIENT_PUB`, `AWG_CLIENT_PUBS`, `AWG_REMOTE`, `AWG_SERVER_PUB` и `AWG_HEADER_PROTECTION_KEY` меняются только связанными действиями панели. |
| `ENV_VARIABLE_NOT_FOUND` | Переменная была удалена после открытия окна. | Закройте и откройте настройки заново. |
| `SERVER_SETTINGS_CONFLICT` | Переменные, адреса, порт или ключ WireGuard были изменены в MikroTik после открытия окна. | Закройте окно, повторно откройте его и внесите изменения в актуальные данные. |
| `SERVER_SETTINGS_ROLLED_BACK` | AWG-контейнер не смог запуститься с новыми настройками. Панель восстановила прежние значения и успешно вернула контейнер в исходное запущенное состояние. | Раскройте «Технические данные»: панель получает причину последнего неудачного запуска через `/container/log/print`, указав имя контейнера. Исправьте параметры и повторите сохранение. |
| `SERVER_ADDRESS_INVALID` | Адрес интерфейса не является IPv4-адресом с CIDR-маской. | Исправьте адрес, например `192.168.177.1/24`. |
| `SERVER_ADDRESS_NOT_FOUND` | Адрес был удалён из MikroTik после открытия окна. | Закройте и откройте настройки заново. |
| `SERVER_ADDRESS_DUPLICATE` | Один адрес введён более одного раза. | Удалите повторяющееся поле. |
| `SERVER_ADDRESSES_EMPTY` | Подготовлено удаление всех адресов WireGuard-интерфейса. | Оставьте или добавьте хотя бы один адрес с маской. |
| `AWG_REMOTE_INVALID` | Текущее значение `AWG_REMOTE` не содержит распознаваемые адрес и порт. | Исправьте `AWG_REMOTE` в MikroTik, затем повторите изменение внутреннего порта. |

## Операции с клиентами

| Код | Что означает | Что сделать |
|---|---|---|
| `CLIENT_KEY_INVALID` | PublicKey, PrivateKey или PresharedKey не является корректным 32-байтовым ключом WireGuard; либо включено хранение ключа, но поле пустое. | Вставьте полный Base64-ключ без лишних символов, сгенерируйте новую пару или отключите соответствующий чекбокс использования/хранения ключа. |
| `CLIENT_KEY_PAIR_MISMATCH` | Введённый PublicKey не соответствует PrivateKey. | Исправьте один из ключей либо нажмите «Сгенерировать новую пару». |
| `ADDRESS_POOL_INVALID` | Выбранная подсеть больше не назначена интерфейсу WireGuard. | Закройте окно, обновите данные и выберите существующий пул. Проверьте активные адреса интерфейса в `/ip/address`. |
| `ADDRESS_POOL_EXHAUSTED` | В выбранной подсети нет свободных адресов. | Выберите другой пул, освободите адрес или добавьте интерфейсу ещё одну подсеть. |
| `ADDRESS_INVALID` | Ручной адрес имеет неверный формат, не входит в выбранную IPv4-подсеть либо является адресом сети/широковещательным адресом. | Введите свободный адрес из выбранной подсети или используйте автоматическую выдачу. |
| `ADDRESS_IN_USE` | Ручной адрес уже занят интерфейсом или другим peer. | Выберите другой адрес либо автоматическую выдачу. |
| `CLIENT_NAME_EXISTS` | Peer с таким именем уже существует на этом интерфейсе. | Укажите другое имя или оставьте поле пустым, чтобы имя назначил RouterOS. |
| `CLIENT_CREATE_FAILED` | После команды добавления RouterOS не вернул созданный peer или его публичный ключ. | Обновите список и проверьте peers на MikroTik. Если peer отсутствует, повторите создание; если проблема повторяется, сохраните технические данные и версию RouterOS. |
| `CLIENT_NOT_FOUND` | Peer был удалён или изменён после загрузки списка. | Обновите список клиентов и повторите действие с существующим peer. |
| `CLIENT_UPDATE_FAILED` | После обновления peer не содержит публичного ключа. | Проверьте peer на MikroTik, исправьте ключи и повторите изменение. |
| `CLIENT_CONFIG_UNAVAILABLE` | `show-client-config` не вернул конфигурацию, из которой можно получить PrivateKey. | Проверьте поддержку команды текущей версией RouterOS и право `sensitive`. Если приватный ключ не хранится в peer, полную конфигурацию восстановить нельзя — используйте исходный PrivateKey клиента. |
| `CLIENT_CONFIG_INVALID` | Для генерации клиентского конфига не удалось получить публичный ключ интерфейса WireGuard. | Проверьте ключ найденного интерфейса и соответствие `AWG_SERVER_PUB`; при необходимости восстановите пару ключей сервера. |

## Общие ошибки панели

| Код | Что означает | Что сделать |
|---|---|---|
| `SERVER_NOT_FOUND` | Браузер запросил сервер, которого больше нет в текущей конфигурации панели. | Обновите страницу. Если сервер был удалён из env, выберите другой сервер; если должен существовать — восстановите его переменные и перезапустите AWGM Admin. |
| `VALIDATION_ERROR` | Одно или несколько полей формы не прошло проверку типа, длины или диапазона. | Проверьте поля формы. В технических данных перечислены имена полей и ограничения. |
| `UNKNOWN_ERROR` | Возникла непредусмотренная внутренняя ошибка. | Повторите действие один раз. Если ошибка сохраняется, сохраните код обращения (`Request ID`), технические данные и журнал, затем создайте обращение в [GitHub Issues](https://github.com/Vozdr/awgm-admin/issues). |
| `NETWORK_ERROR` | Браузер не смог обратиться к панели; этот код создаётся интерфейсом, а не сервером. | Проверьте, что контейнер AWGM Admin работает и адрес панели доступен из браузера. |
| `HTTP_400`, `HTTP_403` и другие `HTTP_<номер>` | Сервер вернул ответ без стандартного объекта ошибки. Обычно это истёкшая сессия, неверный CSRF-токен или неподтверждённое действие. | Обновите страницу и войдите снова. Если ошибка повторяется, раскройте технические данные и проверьте журнал. |

Неверный логин или пароль отображается на странице входа без кода. После нескольких неудачных попыток вход с этого адреса временно ограничивается; дождитесь окончания ограничения и повторите попытку с правильными данными.

## Сообщения журнала, которые не останавливают панель

| Сообщение | Значение |
|---|---|
| `AWG_CONTAINER_STOPPED` | AWG-контейнер остановлен. Панель продолжает работать. Если он остановлен в момент изменения `AWG_CLIENT_PUBS`, переменная обновляется, но панель не запускает и не перезапускает контейнер. |
| `AUTH_DISABLED` | Авторизация отключена переменной `AUTH_DISABLE=yes`. Это предупреждение о безопасности, а не ошибка запуска. |
| `DEFAULT_CREDENTIALS` | Используется стандартная пара `admin/admin`. Панель работает, но логин и пароль следует изменить. |

## Что приложить к сообщению об ошибке

- код ошибки и `Request ID`, если они показаны;
- содержимое блока «Технические данные»;
- версию AWGM Admin внизу страницы;
- версию RouterOS;
- относящиеся к ошибке строки журнала.

Пароли, приватные ключи и `SESSION_SECRET` публиковать не нужно. AWGM Admin скрывает известные секреты в технических данных, но перед отправкой журнала всё равно проверьте его содержимое.
