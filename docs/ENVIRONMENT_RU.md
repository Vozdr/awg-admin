# Переменные окружения AWG Admin

[Главная](../README.md) · [Docker Hub](https://hub.docker.com/r/w03zd8rc/awg-admin) · [Диагностика](TROUBLESHOOTING_RU.md)

AWG Admin не читает локальные конфиги и не использует базу данных. Все параметры приложения задаются через env, а рабочие данные берутся из MikroTik.

## Обязательные параметры

| Переменная | Описание | Пример |
|---|---|---|
| `MIKROTIK_HOST` | IP или DNS-имя MikroTik. Без схемы и порта. | `172.17.0.1` |
| `MIKROTIK_USERNAME` | Пользователь RouterOS API. | `awg-admin` |
| `MIKROTIK_PASSWORD` | Пароль пользователя RouterOS API. | `strong-password` |
| `AWG_CLIENT_ENDPOINT` | Endpoint, который попадёт в клиентские конфиги. Доступность не проверяется. | `vpn.example.org:51820` |

## Подключение к MikroTik

| Переменная | По умолчанию | Описание |
|---|---:|---|
| `MIKROTIK_API_SSL` | `no` | `yes` — API-SSL, `no` — обычный API. |
| `MIKROTIK_API_PORT` | `8729` для SSL, иначе `8728` | Нестандартный порт API. |
| `MIKROTIK_SSL_VERIFY` | `yes` | Проверять сертификат API-SSL. Для самоподписанного сертификата можно указать `no`. |
| `MIKROTIK_CONNECT_TIMEOUT` | `10` | Таймаут подключения, секунд. |
| `MIKROTIK_COMMAND_TIMEOUT` | `20` | Таймаут команды RouterOS, секунд. |

API без TLS допустим, когда панель запущена на том же MikroTik в изолированной контейнерной сети. Для удалённого подключения рекомендуется API-SSL.

## AWG server и новые клиенты

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AWG_CONTAINER_NAME` | `wg-awg-server-1` | Поле `name` или `comment` AWG proxy-контейнера на MikroTik. |
| `AWG_SERVER_NAME` | `AWG Server` | Название профиля в ссылке Amnezia VPN. |
| `CLIENT_DEFAULT_KEEPALIVE` | `30` | Keepalive нового клиента, секунд. `0` отключает его. |
| `CLIENT_DEFAULT_DNS` | пусто | DNS нового клиента. Например `1.1.1.1,8.8.8.8`. |
| `CLIENT_DEFAULT_ALLOWED_IPS` | `0.0.0.0/0,::/0` | AllowedIPs нового клиента. |

Пулы адресов не задаются через env. Панель получает все активные IPv4-адреса, назначенные найденному интерфейсу WireGuard, строит из них подсети и предлагает выбрать одну при создании клиента.

## Авторизация панели

| Переменная | По умолчанию | Описание |
|---|---|---|
| `ADMIN_USERNAME` | `admin` | Логин панели. Может быть задан без `ADMIN_PASSWORD`. |
| `ADMIN_PASSWORD` | `admin` | Пароль панели. Может быть задан без `ADMIN_USERNAME`. |
| `AUTH_DISABLE` | `no` | `yes` полностью отключает авторизацию. Панель запишет сообщение уровня ERROR, но продолжит работу. |
| `SESSION_SECRET` | случайный при каждом запуске | Ключ подписи сессий и CSRF. Укажите длинную случайную строку, чтобы сессии переживали перезапуск. |
| `COOKIE_SECURE` | `no` | `yes` отправляет cookie только через HTTPS. Не включайте при прямом доступе по HTTP. |

Если логин и пароль не указаны, применяются `admin/admin`, а в лог записывается предупреждение уровня ERROR.

## Интерфейс и журнал

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DEFAULT_LANG` | `ru` | Начальная локаль: `ru` или `en`. Выбор пользователя сохраняется в браузере. |
| `DEFAULT_THEME` | `dark` | Начальная тема: `dark` или `light`. |
| `LOG_LEVEL` | `INFO` | Уровень журнала Python: `DEBUG`, `INFO`, `WARNING`, `ERROR`. |
| `LOCALES_DIR` | `/app/locales` | Внутренний путь к локалям. Обычно менять не требуется. |
| `AWG_ADMIN_VERSION` | `dev` | Служебная версия сборки. Автоматически задаётся при публикации образа. |

Булевы параметры принимают `yes/no`, `true/false`, `on/off` и `1/0` без учёта регистра.
